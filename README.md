# ya-maps-xr (Godot / OpenXR)

Порт `ya_maps_webxr` на автономный Android-шлем (OpenXR): Godot 4.7.2.
Приложение ставится как APK, запускается из библиотеки шлема и стартует сразу
в VR — без ПК, браузера и локального сервера.

## Возможности

- **Панорамы Яндекса в VR** — уличные и воздушные, с переходами по стрелкам.
- **Планшет с картой**: непрерывный зум и сдвиг (тайловая пирамида Яндекса),
  переключаемый слой панорам, поиск мест с собственной клавиатурой (RU/EN),
  «переход между городами».
- **Поиск мест работает без ключа API** (подсказки через `suggest-maps`).
- Приближение панорамы левым стиком.
- **Контроллеры видны в руках** — 3D-модели в позе захвата, с откликом на нажатия
  (курок, грип, кнопки, стик). Пока показан планшет, левый контроллер скрыт.

## Управление

- **Левый стик**: горизонталь — поворот вокруг своей оси, вертикаль —
  приближение панорамы.
- **Правый стик**: плавный (непрерывный) зум карты.
- **Правый триггер**: клик/перетаскивание по планшету (кнопки UI и карта).
- **Левый триггер**: клик по стрелкам перехода.
- **A/X**: показать/скрыть планшет.

## Тулчейн

Уже установлено в этой системе (без sudo, в `~/.local`):

| Компонент | Путь / версия |
|---|---|
| Godot | `~/.local/opt/godot-4.7.2/`, симлинк `~/.local/bin/godot` |
| JDK | `~/.local/opt/jdk-17` (Temurin 17.0.21) |
| Android SDK | `~/Android/Sdk` (platform-tools, platforms 35/36, build-tools 35/36) |
| Шаблоны экспорта | `~/.local/share/godot/export_templates/4.7.2.stable/` |

Переменные окружения (`JAVA_HOME`, `ANDROID_HOME`, `PATH`) прописаны в
`~/.zshrc` и `~/.bashrc`.

## Ключ API (необязателен)

`scripts/config.gd` лежит в репозитории, ключи в нём пустые:

```gdscript
const YANDEX_API_KEY := ""
const YANDEX_STATIC_KEY := ""
```

Ключ **не нужен**: сервис панорам его не проверяет, и приложение работает с
пустым `YANDEX_API_KEY`. Если ключ понадобится, он берётся из соседнего проекта
(`../ya_maps_webxr/.env`).

Вписанный в `config.gd` ключ уходит и в репозиторий, и в APK (оттуда извлекается)
— для публикации нужен прокси (как `server/api.mjs` в веб-версии).

## Плагин OpenXR Vendors

Аддон `addons/godotopenxrvendors` вендорится из upstream
(`GodotVR/godot_openxr_vendors`, релиз `5.2.0-stable`). В git лежат только
текстовые файлы плагина; бинари (`.bin/`, ~50 МБ) не коммитятся и
подтягиваются из релизного zip:

```bash
./fetch_addon.sh                  # версия из скрипта (5.2.0-stable)
./fetch_addon.sh 5.1.0-stable     # другая версия
./fetch_addon.sh --check          # проверить, что бинари на месте
```

Скрипт сверяет sha256 скачанного архива. **Без этого шага проект не запустится
и не соберётся** — Godot грузит `.so/.dll/.aar` прямо из `res://addons/...`.

## Сборка

```bash
# debug APK (подписан debug-ключом Godot)
godot --headless --path . --export-debug "Android" build/ya-maps-xr.apk

# release
godot --headless --path . --export-release "Android" build/ya-maps-xr.apk
```

Сборка идёт через Gradle (`android/build/`) — это нужно для плагина OpenXR
Vendors. Первый билд дольше: Gradle качает зависимости.

## Установка на шлем

1. Включите на шлеме режим разработчика и отладку по USB.
2. Подключите по USB и проверьте: `adb devices`.
3. `adb install -r build/ya-maps-xr.apk`
4. Приложение появится в библиотеке шлема.

В WSL2 USB-устройства не видны. Варианты:
- запускать `adb` на стороне Windows (platform-tools), либо
- один раз выполнить на Windows `adb tcpip 5555`, затем из WSL
  `adb connect <IP-шлема>:5555` (шлем и ПК в одной сети).

## Запуск на десктопе (отладка логики)

```bash
godot --path . --xr-mode off            # окно с 2D-превью
godot --path . --xr-mode off -- --dump  # сохранить текстуры (панорама + карта в dump/)

# кадр планшета без загрузки панорамы (UI/карта/оверлей/клавиатура):
godot --path . --xr-mode off -- --ui-shot [--overlay] [--keyboard] [--ll=lon,lat]

# воздушная панорама по точке (отладка соседей-маркеров):
godot --path . --xr-mode off -- --shot --air --ll=37.67169,55.914 --yaw=64 --pitch=-36

# самопроверка поиска (подсказки + координаты):
godot --path . --xr-mode off -- --search-test

# модели контроллеров (снимки с нескольких сторон, без загрузки панорамы):
godot --path . --xr-mode off -- --hands-shot [--both] [--islands] [--press]
```

`--ui-shot`/`--search-test`/`--hands-shot`/`--ll`/`--air` работают и без XR-шлема.

`--xr-mode off` обязателен: без OpenXR-рантайма Godot в headless-режиме
зависает на инициализации XR.

## Структура

```
scenes/main.tscn        — единственный узел Main со скриптом
scripts/main.gd         — XR-риг, сцена, ввод, загрузка панорамы
scripts/panorama.gd     — метаданные, нормализация JSON, склейка тайлов
scripts/pano_stream.gd  — сектора сферы: геометрия, ленивая загрузка, LOD
scripts/pano_view.gd    — один вид панорамы: сфера, стрелки/маркеры, стример
scripts/map_tablet.gd   — планшет: SubViewport, дробный зум, маркер, тап по карте
scripts/map_tiles.gd    — тайловый движок карты + оверлей панорам (EPSG:3395)
scripts/tablet_ui.gd    — UI планшета: поиск, клавиатура, тоггл, маркер (Control)
scripts/search.gd       — подсказки мест без ключа + разбор координат из uri
scripts/geo.gd          — Меркатор (сферический + EPSG:3395)
scripts/net.gd          — HTTPRequest + Referer
scripts/config.gd       — ключи (необязательные, по умолчанию пустые) и константы
shaders/                — шейдеры сферы-панорамы и секторов
assets/                 — иконка дирижабля и модели контроллеров
android/build/          — Gradle-шаблон экспорта + правки манифеста
addons/godotopenxrvendors — OpenXR Vendors 5.2.0 (бинари тянутся ./fetch_addon.sh)
```

## Известные ограничения

- Ввод (луч, триггер, стик) проверяется только на устройстве.
- Квота Яндекса: сервис панорам троттлит по IP (ответ `limited` при частых
  запросах); официальной статистики по бесплатному ключу Яндекс не даёт.
- Воздушную панораму сервис ищет в радиусе ~80 м (уличную — ~400 м): тап по
  пустому месту воздушную не найдёт, нужен тап по иконке слоя панорам.
- Результаты поиска-организации (`ymapsbm1://org`) координат не содержат и в
  списке не кликабельны (нужна отдельная геокодировка, ключ).
- UI планшета (`SubViewport` + своя клавиатура) и ввод рейком проверены на
  десктопе (Xvfb), на устройствах ещё не гонялись; `suggest-geo` и
  `core-stv-renderer` — неофициальные ручки, могут измениться.
