# Планшет/UI в ya-maps-xr: brainstorm / discovery
Date: 2026-11-12 · Цель: переработать UI в планшете — плавный зум, оверлей панорам с тогглом, открытие воздушных панорам с HUD-маркерами соседей, поиск мест и переход между городами.

> Итоговый инженерный план: `docs/tablet-ui-plan.md` (этапы 1–3, файлы, критерии готовности).

## Что просит пользователь (изначально)
1. Зум не ступеньками, а плавный.
2. Панорамный оверлей с тогглом.
3. Открывать панорамы воздушной съёмки (`sta`) и показывать в HUD маркеры соседних панорам для таких панорам.
4. Строка поиска географических мест + переход между городами через поиск.

## Контекст из кода (состояние до переработки)
- Зум ступенчатый: `map_tablet.gd:zoom_by(±1)`, правый стик с защёлкой (`main.gd:_poll_controllers`). Каждый шаг = новая мозаика 3×3 Static API (650×450 на ячейку). Static API принимает только целый `z`.
- Оверлей панорам уже исследован: `docs/panorama-layer-research.md`. Растровые тайлы `core-stv-renderer.maps.yandex.net/2.x/tiles?l=stv|sta`, проекция EPSG:3395 (≠ текущая сферическая `geo.gd`), порог зума ≥13.
- Планшет — 3D-меш (`QuadMesh`) с текстурой-мозаикой; отдельного UI нет.
- Ввод: A/X — показать/скрыть планшет; правый стик — зум карты; триггер — драг/клик; левый триггер — клик по шевронам.
- Воздушные панорамы в приложении сейчас не открываются вообще (всё идёт через `l=stv`).

## Ключевые решения (сводка)
1. **Плавный зум** — непрерывный дробный (текстура масштабируется дробно, целые z только для запросов).
2. **Основа карты** — переход с мозаики Static API 3×3 на тайловую пирамиду `core-renderer-tiles` (`l=map`), проекция EPSG:3395 (общая с оверлеем).
3. **Оверлей** — один тоггл «Панорамы» (stv+sta), виден с z≥13, по умолчанию выкл, состояние в `State`.
4. **Открытие воздушных панорам** — по точке, как уличные: `l=sta&ll=...` (радиус ~80 м). Векторные тайлы/protobuf не нужны.
5. **HUD-маркеры соседей воздушной панорамы** — из `Annotation.Connections`, шевроны голубого цвета, позиция по yaw+pitch из координат, клик → открыть соседа по oid.
6. **Тап по карте** — сэмпл альфы оверлея: sta-иконка → воздушная, иначе stv → уличная, пусто → ближайшая панорама (как сейчас).
7. **Технология UI планшета** — `SubViewport` + `Control`-ноды, отрисовка в текстуру; ввод рейкастом → синтетические события.
8. **Раскладка** — карта на весь планшет, строка поиска сверху (+ тоггл в углу), клавиатура выезжает снизу.
9. **Ввод текста** — собственная клавиатура на планшете, RU+EN с переключением, цифры/символы отдельным рядом.
10. **Поиск** — ключесс `suggest-maps.yandex.ru/suggest-geo` + мини-декодер координат из `uri` (base64 → float32).
11. **Выбор результата** — центрировать карту + метка (город ~z12, место ~z16); «переход между городами» = перелёт карты, не телепорт панорамы.
12. **Управление зумом** — правый стик = скорость изменения дробного zoom, диапазон z3–z19.
13. **Порядок работ** — фундамент → оверлей → UI-поиск.

## Находки из API-проб (2026-11-12, важное)
- **Воздушные панорамы открываются по точке так же, как уличные:** `.../panoramas/1.x/?l=sta&ll=<lon>,<lat>&origin=userAction` → 200, если воздушная панорама в радиусе ~80 м (60 м — ок, 100 м — 404). `l=stv` по точке работает до ~400 м (400 м — ок, 800 м — 404). То есть клик по иконке оверлея → `fetch_by_ll` с нужным слоем; ни векторные тайлы, ни разбор protobuf, ни собственный каталог id не нужны (первоначальная гипотеза из research-doc не подтвердилась — by-ll для sta работает).
- `provider` в сервисе панорам по сути игнорируется (с `provider=air`/`streetview`/пусто по oid — одинаково; пусто по ll → 400). В приложении нужно слать непустой `provider`.
- Соседи воздушных панорам — в `Annotation.Connections`: `{name, Point.coordinates:[lon,lat,alt], href:<oid+provider=air+l=sta>, style:#airshipStyle}`. `Thoroughfares`/`Graph` у них пустые. Направление считаем сами из координат.
- Базовая карта `core-renderer-tiles.maps.yandex.ru/tiles?l=map&...&format=png` отдаёт PNG 200 без ключа/кук. Комбинированный `l=map,stv,sta` там запрещён (404) — оверлей stv/sta берём отдельно с `core-stv-renderer`.
- Геокодер `geocode-maps.yandex.ru` требует apikey; **ключ из `../ya_maps_webxr/.env` для него невалиден** (403 «Invalid api key»).
- **Поиск без ключа возможен**: `suggest-maps.yandex.ru/suggest-geo?part=...&v=9&lang=ru&n=..` → 200 без ключа, отдаёт топонимы/организации с `uri` вида `ymapsbm1://geo?data=<base64>`; внутри — координаты как float32 (проверено: Москва ≈ 37.617, 55.756). Неофициальная ручка, нужен мини-декодер.

## Q&A log

### Q1 — Семантика плавного зума
- Asked: непрерывный дробный зум / анимированные целые шаги / гибрид с доводкой?
- Captured: **Непрерывный дробный зум.** Пока движешь — текстура карты масштабируется дробно (uv scale), при пересечении целого z подгружается новая мозаика. В движении мягко, в покое резко. Целые z остаются только для запросов к Static API.
- Flags: —

### Q2 — Основа карты: тайловая пирамида вместо Static API
- Asked: оставить Static API (мозаика 3×3) или перейти на core-renderer-tiles (та же сетка/проекция EPSG:3395, что у оверлея)?
- Captured: **Переходим на core-renderer-tiles (`l=map`).** Одна тайловая сетка и проекция для базы и оверлея панорам; убирает «прыжки» мозаики 3×3 и упрощает непрерывный зум/сдвиг. Больше работы, но снимает будущий долг.
- Следствия: `geo.gd` нужен EPSG:3395 (`yandex_world_px`), `map_tablet.gd` переписывается на тайловый движок с кэшем/LRU и пирамидой уровней.
- Flags: подтвердить формат/лимиты core-renderer-tiles (нужен ли Referer/ключ, какие варианты `l=map`) — проверить при реализации.

### Q3 — Тоггл панорамного оверлея
- Asked: один «Панорамы» / два (улицы/воздушные) / цикл режимов?
- Captured: **Один тоггл «Панорамы»** — рисует stv+sta (линии покрытия + иконки) поверх базы; ниже z13 скрыт; иконки кликабельны (клик → `fetch_by_ll` по нужному слою).
- Flags: —

### Q4 — Ввод текста поиска в шлеме
- Asked: системная клавиатура Pico / своя 3D-клавиатура / без набора / гибрид?
- Captured: **Своя клавиатура прямо в планшете, с русской раскладкой по умолчанию.** Не системная IME. Скоуп работы заметный.
- Flags: как размещать клавиатуру, чтобы не закрывать карту (закрыто в Q8 — выезжает снизу).

### Q5 — Бэкенд поиска
- Asked: ключесс suggest-maps / Geocoder API с ключом / гибрид?
- Captured: **Ключесс: `suggest-maps.yandex.ru/suggest-geo`** — подсказки по мере ввода + мини-декодер координат из поля `uri` (base64 → float32). Без ключа, работает сейчас; ручка неофициальная (как слой панорам).
- Flags: формат ответа suggest нестабилен — нужен мягкий разбор и фолбэк; нет структурированных bbox/адресов.

### Q6 — Поведение при выборе результата поиска
- Asked: центровать карту / сразу открыть панораму / два шага?
- Captured: **Центровать карту + метка.** Город → центр + зум ~12; место/адрес → центр + зум ~16 и метка. Автоматически в панораму не уходим. «Переход между городами» = перелёт *карты* к городу, не телепорт панорамы.
- Flags: —

### Q7 — Технология UI планшета
- Asked: SubViewport + Control / нативные 3D-квады / гибрид?
- Captured: **SubViewport + Control.** UI планшета — обычные Control-ноды в SubViewport, отрисовка в текстуру на плоскости; ввод — рейкаст → синтетические события. Карта — фон в том же UI.
- Flags: как именно прокидывать XR-рей/триггер в SubViewport (синтетические `InputEvent`) — проверить на устройстве.

### Q8 — Раскладка планшета
- Asked: как расположить карту / поиск / клавиатуру / тоггл?
- Captured: **Поиск сверху (строка + тоггл в углу), клавиатура выезжает снизу поверх карты** при активном поле, иначе скрыта. Карта на весь планшет.
- Flags: —

### Q9 — HUD-маркеры соседей воздушной панорамы
- Asked: шевроны с pitch / иконка с подписью / точки?
- Captured: **Те же шевроны, но голубого «воздушного» цвета; позиция — по направлению из координат (yaw и pitch), маркер висит выше/ниже горизонта; клик открывает соседа по oid.**
- Flags: `Connection.style` бывает `#airshipStyle` — можно использовать как признак «воздушный».

### Q10 — Тап по карте в режиме оверлея
- Asked: только по иконкам / по слою с фолбэком / просто stv→sta?
- Captured: **Сэмпл альфы оверлея под тапом:** есть иконка sta → воздушная; иначе иконка stv → уличная; пустое место → как сейчас, ближайшая панорама (`fetch_by_ll` stv). Значит stv и sta рисуем отдельными слоями, чтобы различать иконки.
- Flags: тап-порог «попал в иконку» (несколько px) и приоритет, если под тапом оказались и stv, и sta.

### Q11 — Управление непрерывным зумом
- Asked: стик = скорость / абсолютный уровень / стик+жесты?
- Captured: **Правый стик = скорость изменения дробного zoom**, с плавной кривой, без защёлки; диапазон как сейчас z3–z19; драг на карте — только панорамирование.
- Flags: коэффициенты скорости/кривой и дед-зона — тюнинг на устройстве.

### Q11b — Скоуп и последовательность
- Asked: порядок работ (фундамент → оверлей → UI / победы сначала / всё сразу)?
- Captured: **Фундамент → оверлей → UI-поиск.** Этап 1: EPSG-проекция (`geo.gd`) + тайловый движок базы (`map_tablet.gd`) + дробный зум. Этап 2: оверлей stv/sta + клик по иконкам по слою + открытие воздушных панорам + HUD-маркеры соседей. Этап 3: SubViewport-UI — строка поиска, клавиатура, тоггл. Каждый этап самостоятельно ставится на шлем.
- Flags (дефолты на реализацию, подтверждены в Q13): тоггл по умолчанию выкл; состояние в `State`; порог оверлея z≥13; отладочные пути `--shot`/`--dump`/2D-превью сохраняем.

### Q12 — Раскладки встроенной клавиатуры
- Asked: только RU / RU+EN / полный набор?
- Captured: **RU + EN с переключателем на самой клавиатуре**, цифры и основные символы — отдельным слоем/рядом.
- Flags: —

### Q13 — Остальные дефолты
