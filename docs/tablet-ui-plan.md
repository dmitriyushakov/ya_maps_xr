# План: переработка UI планшета в ya-maps-xr

Дата: 2026-11-12 · Источник решений: `brainstorms/2026-11-12-tablet-ui.md`

## Статус: реализовано (все три этапа)

Код написан и проверен на десктопе (`godot --xr-mode off` под Xvfb): карта-пирамида
EPSG:3395, дробный зум, оверлей `stv`+`sta`, открытие воздушной панорамы с голубыми
маркерами соседей, поиск с собственной клавиатурой RU/EN. Скрипты проходят
`--check-only`. На устройстве не гонялось.

Отличия от плана при реализации:
- **Ввод UI — не через `push_input` в `SubViewport`** (пункт «риски»), а явной
  диспетчеризацией: `main.gd` считает пиксель попадания и зовёт
  `tablet.ui_press/ui_release`; кнопки — обычные `Button`, у каждой в meta лежит
  действие. Меньше платформозависимости.
- **Карта занимает весь SubViewport**, а не отдельный меш с текстурой: плоскость
  показывает `SubViewportTexture`, карта — фон-`TextureRect` внутри UI.
- **Маркер «вы здесь» рисуется в 2D** (`tablet_ui._draw_marker`), а не 3D-мешем.
- **Поиск — ключесс** `suggest-geo` + разбор protobuf из `uri` (в плане был
  мягкий декодер; реализован как строгий protobuf-обход, отдельно отсеивающий
  строки/случайные байты). Организации без координат — не кликабельны.

Отладочные команды: `-- --ui-shot [--overlay] [--keyboard] [--ll=lon,lat]`,
`-- --shot --air --ll=lon,lat`, `-- --search-test` (см. README).

## Цель и скоуп

Перевести планшет с мозаики Static API на тайловую пирамиду, сделать непрерывный
зум, добавить панорамный оверлей с тогглом, открытие воздушных панорам с HUD-
маркерами соседей и поиск с собственной клавиатурой.

Порядок работ (подтверждён):
**Этап 1 (фундамент) → Этап 2 (оверлей + воздушные панорамы) → Этап 3 (UI/поиск).**
Каждый этап самостоятельно собирается и ставится на шлем.

### НЕ входит в скоуп
- Изменение сферы-панорамы/секторов (`pano_stream.gd`, шейдеры) — не трогаем.
- Системная IME/голосовой ввод.
- Переходы между *панорамами* разных городов одной кнопкой — «переход между
  городами» делается перелётом **карты** (см. Этап 3).

## Этап 1 — фундамент: EPSG:3395 + тайловый движок + непрерывный зум

### 1.1 `scripts/geo.gd`: проекция EPSG:3395
Добавить рядом с существующей сферической (её использует `pano`? — нет, только карта,
так что можно оставить, но `map_*` перевести на EPSG):

```gdscript
const A := 6378137.0
const E := 0.0818191908426  # sqrt(1-(b/a)^2)

static func yandex_world_px(lon: float, lat: float, zoom: float) -> Vector2:
	var ph := deg_to_rad(clamp_lat(lat))
	var ym := A * log(tan(PI / 4.0 + ph / 2.0) * pow((1.0 - E * sin(ph)) / (1.0 + E * sin(ph)), E / 2.0))
	var s := WORLD_TILE * pow(2.0, zoom)
	return Vector2((lon + 180.0) / 360.0 * s, (1.0 - ym / (A * PI)) / 2.0 * s)
```

- Обратную (`yandex_lon_lat`) считать **итеративно** (обратный Меркатор для
  эллипсоида): 3–4 итерации Ньютона по φ, достаточно суб-пиксельной точности.
- `zoom` — float (для дробного зума; целые уровни дают целые `s`).
- Существующие `lon_lat_to_world_px` / `world_px_to_lon_lat` оставить для отладки,
  но `map_tablet.gd` перевести на `yandex_*`.

Проверка: тайл `(79233, 41090, 17)` для 55.7539, 37.6208 совпадает по EPSG-формуле
(см. `docs/panorama-layer-research.md` §3.3).

### 1.2 `scripts/map_tiles.gd`: тайловый движок (новый)
`RefCounted`, без 3D-зависимостей.

**API:**
- `setup(viewport_px: Vector2i, workers: int) -> void`
- `build(center: Vector2 /*lon,lat*/, zoom: float, overlay: bool) -> ImageTexture` (await)
  - `z0 = floori(zoom)`; тайлы уровня `z0`; дробная часть `zoom - z0` обрабатывается
    **UV-скейлом в материале** (см. 1.3), движок отдаёт текстуру уровня `z0`.
- `sample_overlay(pixel: Vector2i) -> int` — `-1` нет иконки, `0` stv, `1` sta.
- `set_overlay(enabled: bool)`.

**Источники:**
- База: `https://core-renderer-tiles.maps.yandex.ru/tiles?l=map&x={x}&y={y}&z={z}&format=png`
  (проверено: 256px PNG, 200 без ключа/Referer/cookies, z12–z21; **шардированные
  хосты вида `01.` у базовой карты НЕ работают** — только нешардированный хост).
- Оверлей: `https://0{1..4}.core-stv-renderer.maps.yandex.net/2.x/tiles?l=stv|sta&x&y&z&scale=1&lang=ru_RU&format=png&v=1`
  (`v` непустой, значение не проверяется; `204` = нет покрытия).

**Устройство:**
- Тайлы обоих источников — в одной сетке (EPSG:3395, 256px) → `x/y/z` общие.
- Видимое окно: центр в px (`yandex_world_px(center, z0)`), прямоугольник
  `viewport_px`, диапазон тайлов `floor((center - view/2)/256)` … `ceil(...)` с
  перекрытием (не более ~5×4 тайлов на слой).
- Кэш: LRU `Dict[Vector3i(z,x,y)] -> Image`; лимит ~200 тайлов (память ~25 МБ).
  При движении — префетч краевых тайлов.
- Сборка: `Image.create(viewport)` → блит базовых тайлов со смещением; при
  `overlay` и `z0 >= 13` — поверх блит stv- и sta-слоёв. Оверлей держим
  **отдельными Image** (или отдельными текстурами), чтобы сэмплить альфу под тапом.
- Запросы — через `Net.get_bytes`, пул воркеров (как `map_tablet._load_worker`),
  ограничение параллелизма (`MAP_WORKERS`), при `204` — пустой тайл (не ошибка).
- `--dump` сохраняет собранную карту (перенести из `map_tablet.request`).

**Важно:** оверлей-тайлы нужны только при `overlay && z0>=13`; при меньших зумах
не запрашиваем (меньше запросов и мусора).

### 1.3 `scripts/map_tablet.gd`: переписать на движок + дробный зум
- Плоскость, рамка, маркер «вы здесь» (`here_root`) — сохранить.
- `zoom` становится `float`. Добавить `set_zoom(f: float)`:
  - Обновляет `material.uv1_scale`/`uv1_offset` от дробной части: масштаб
    `2^(zoom - z0)`; при пересечении целого порога — запрос новых тайлов.
  - Плавно, без «шага»: пока движешь, крутится UV; при смене `z0` — подмена текстуры.
- Сдвиг (`preview_drag`) — как сейчас, но окно больше не ограничено мозаикой 3×3:
  тайлы догружаются по краю (заменить `MAX_OFFSET_*`/`REFRESH_AT_*` на префетч).
- `lon_lat_at_local` / `local_at_lon_lat` — перевести на `Geo.yandex_*`.
- Текстуру брать у движка: `map_tiles.build(...)`.

### 1.4 `scripts/main.gd`: непрерывный зум
- Убрать защёлку (`_stick_latched`) и `tablet.zoom_by(±1)`.
- Правый стик: `tablet.set_zoom(zoom + stick.y * MAP_ZOOM_RATE * delta)` с плавной
  кривой (например `sign*|x|^1.5`), кламп `z3..z19`; дед-зона как у поворота.
- Имена: `_zoom` (приближение панорамы) оставить; новый зум карты — `_map_zoom`
  или внутри планшета.
- `_save_state()`/`State` — писать `zoom` как float.

## Этап 2 — оверлей панорам + воздушные панорамы + маркеры соседей

### 2.1 Оверлей stv/sta (в `map_tiles.gd` + тоггл в `main.gd`)
- Загрузка/блит двух слоёв (см. 1.2), видимость `z >= 13`.
- Тоггл: `State.set_value("overlay_pano", bool)`; по умолчанию **выкл**.
- Управление тогглом: временно (до Э3) — кнопка контроллера (напр. `ax_button`
  свободен? — он занят показом планшета; использовать `by_button` или комбинацию);
  окончательно — кнопка в UI планшета (Э3).
- Хранить координаты тайлов/смещение, чтобы уметь `sample_overlay(pixel)`.
  Хранить отсчёт альфы: `Image.get_pixel(...).a > 0`.

### 2.2 `scripts/panorama.gd`: слой по точке + разбор Connection
- `fetch_by_ll(lon, lat, layer := "stv")`: подставлять `l=<layer>` и `provider`
  (`streetview`/`air`); для `sta` радиус поиска ~80 м, для `stv` ~400 м —
  учитывать при пороге «нашли/нет».
- Разбор `Annotation.Connections` (для воздушных): `[{oid, name, lon, lat, alt, air}]`,
  где `oid` — из `href` (`_oid_from_href` уже есть), `air = style.ends_with("#airshipStyle")`
  или `layer=="sta"`.
- `fetch_by_id` — оставить: по oid `l`/`provider` не важны (проверено, сервис
  игнорирует). Добавить в результат `air_links`.
- `from_payload`: добавить `conns` в возвращаемый словарь; `lon/lat/alt` текущей
  панорамы брать из `Point.coordinates` (3-й компонент — высота).

### 2.3 `scripts/pano_view.gd`: маркеры с pitch и цветом
- Добавить `build_markers(items: Array, color: Color)`, где элемент
  `{id, name, dir: Vector3}` — направление в локальном фрейме сферы.
- Позиция: `pos = Vector3(dir.x, dir.y, dir.z) * ARROW_RADIUS` (dir — единичный,
  уже с yaw+pitch), `group.rotation.y = -yaw`; при желании наклонять квад к камере.
- Цвет воздушных — голубой (напр. `Color(0.25,0.7,1.0)`); уличные — как сейчас.
- `hide_arrows`/`_apply_arrows_fade`/`set_priority` должны уметь и новые маркеры
  (итерировать по обоим наборам либо хранить один список групп).

### 2.4 `scripts/main.gd`: направление из координат + открытие воздушных
- Вычисление направления (ENU): для соседа
  `east = dlon*cos(lat)`, `north = dlat`, `up = dalt` (метры, грубая оценка),
  `yaw = atan2(east, north)`, `pitch = atan2(up, hypot(east, north))`.
  Север = `-Z` (та же конвенция, что у `Thoroughfares`), поэтому
  `dir = Vector3(sin(yaw)*cos(pitch), sin(pitch), -cos(yaw)*cos(pitch))`.
- Выбор источника стрелок при `_apply_panorama`: если `links` пустой, а
  `conns` непустой — строим маркеры из Connection (воздушная панорама);
  иначе — как сейчас (`Thoroughfares`). `_last_links` — для префетча (у воздушных
  соседей префетч по oid тоже работает).
- Клик по маркеру: `_resolve_ray` уже читает `link.id` → `_go_to_id(id, yaw)`
  работает и для воздушных (по oid `l` не важен).
- Тап по карте: `layer = tablet.sample_overlay(px)`; `0` → `fetch_by_ll(...,"stv")`,
  `1` → `fetch_by_ll(...,"sta")`, `-1` → как сейчас (stv, ближайшая).
  Порог «попал в иконку» — несколько px (сэмплить 3×3 вокруг точки).

### Критерии готовности этапа 2
- Тоггл включает/выключает линии покрытия и иконки (с z13), состояние запоминается.
- Клик по иконке воздушной панорамы открывает её (спарсен `l=sta`).
- У воздушной панорамы видны голубые маркеры соседей выше/ниже горизонта; клик
  открывает соседа.
- Обычные уличные панорамы и стрелки не сломаны.

## Этап 3 — UI планшета: поиск, клавиатура, тоггл

### 3.1 `SubViewport` + Control вместо текстуры на плоскости
- Добавить `SubViewport` (напр. `1024×712` для чёткого текста) + `Control`-дерево
  (`scenes/tablet_ui.tscn`):
  - фон — `TextureRect` с текстурой карты (её отдаёт `map_tiles`/`map_tablet`);
  - верхняя панель: поле поиска (отображение текста + кнопка «очистить»),
    выпадающий список подсказок, кнопка-тоггл «Панорамы» в углу;
  - клавиатура — `PanelContainer` + `GridContainer` кнопок, выезжает снизу
    (`Tween` на `position.y`), когда поле активно.
- Плоскость планшета показывает `SubViewportTexture`.
- Ввод: рейкаст по плоскости (существующий `_tablet_hit`) → локальные координаты →
  координаты субвьюпорта → `subviewport.push_input(InputEventMouseMotion/Button, true)`.
  Отдельный тест: попадание, драг, нажатие кнопки.

### 3.2 `scripts/search.gd` — поиск без ключа
- `suggest(part: String) -> Array` (await):
  `https://suggest-maps.yandex.ru/suggest-geo?part=<enc>&v=9&lang=ru&n=8&search_type=all`
  → разбор `suggest.apply({...})` (JSONP-обёртка!) → список
  `{title, subtitle, tags, uri}`.
- Декодер координат из `uri`: `ymapsbm1://geo?data=<base64url>` → base64url-decode →
  сканировать float32 LE пары в разумных диапазонах (`lon ∈ [-180,180]`,
  `lat ∈ [-90,90]`) → берём наиболее правдоподобную пару (проверено: Москва
  ≈ 37.617, 55.756). Мягкий разбор: если не нашли — результат без координат,
  не показываем как кликабельный (фолбэк).
- `is_city(tags, subtitle)`: по `tags`/`subtitle` (например `distance` присутствует →
  ранжирование по близости); тип «город» определять по `tags` (`locality`) или по
  формату ответа.
- Дебаунс ввода (~250 мс), отмена устаревших запросов по токену.

### 3.3 Клавиатура (`tablet_ui.gd` / данные раскладок)
- Раскладки RU и EN (массивы строк), переключатель; отдельный ряд цифр/символов.
- Кнопки: буквы, `Пробел`, `⌫`, `Ent`, переключатель RU/EN.
- Нажатие (mouse event из рейки) → добавить/удалить символ в строке запроса.
- Показать/скрыть по фокусу поля; не закрывать карту полностью (выезжает снизу).

### 3.4 Выбор результата
- Тап по подсказке → `Geo.yandex_world_px` → центрировать карту:
  город → `z≈12`, место → `z≈16`; поставить метку (можно переиспользовать
  `set_here`-подобную метку «найдено», отдельную от «вы здесь»).
- Скрыть клавиатуру, очистить/оставить строку.
- Сохранить в `State` последний запрос/город (по желанию).

### Критерии готовности этапа 3
- Строка поиска набирается своей клавиатурой (RU/EN) в шлеме.
- Подсказки приходят без ключа; выбор центрирует карту и ставит метку.
- Тоггл «Панорамы» — кнопка в UI, состояние сохраняется.
- Отладочный 2D-превью работает (`--xr-mode off`), `--shot`/`--dump` целы.

## Риски и меры

| Риск | Мера |
|---|---|
| Много тайловых запросов → троттлинг (по IP общий с панорамами) | LRU-кэш, префетч только краевых, лимит параллелизма, не грузить оверлей ниже z13 |
| Обратный EPSG:3395 (эллипсоид) | Итеративный Ньютон (3–4 шага), юнит-проверка против известного тайла |
| Прокид XR-рей/триггера в `SubViewport` | Отдельная отладочная сцена/режим, проверка на устройстве; при проблемах — синтетические события на `Control` напрямую |
| Неофициальный `suggest-geo` изменится | Мягкий разбор + фолбэк (без координат — не кликабельно) |
| Воздушные панорамы разрежены (радиус ~80 м) | Явно показывать «нет панорамы рядом», не телепортить наугад |
| Клавиатура в VR неудобна | Компактная сетка, крупные кнопки, RU по умолчанию, цифры отдельно |
| Регресс отладочных путей | Сохранить `--shot`/`--dump`/2D-превью, проверить в каждом этапе |
