# Проекция equirect-развёртки панорам Яндекса

Дата: 2026-11-12. Область: `scripts/panorama.gd`, `scripts/pano_stream.gd`,
`scripts/pano_view.gd`, `shaders/panorama.gdshader`, `shaders/pano_patch.gdshader`.

Коротко: **equirect Яндекса — не всегда «полный шар 2:1»**. Вертикальный охват
развёртки зависит от отношения сторон картинки, а `Origin[1]` — это широта середины
картинки, а не наклон сферы. Приложение обязано считать геометрию из метаданных;
жёсткое предположение «полный шар» (`v = acos(y)/π`) верно только при `H/W = 0.5`.

## Origin = [azimuth, horizonTilt]

`Data.EquirectangularProjection.Origin = [azimuth, horizonTilt]`, оба в градусах.

- `azimuth` — азимут шва (нулевого столбца). Идёт в `yaw_origin` (плюс `YAW_FIX_DEG`).
- `horizonTilt` — **широта середины панорамного изображения** (строка `v = 0.5`). Это
  не верхняя граница и не наклон всей сферической системы координат поворотом
  вокруг оси X.

## Вертикальная геометрия

Верхний край развёртки привязан к зениту по **самому мелкому** уровню (у него
размеры сильнее всего округлены, поэтому порог лечит округление):

```text
colatitude_top = π/2 − π·H_low/W_low − radians(horizonTilt)
if colatitude_top < π/100:      # порог ≈ 1.8°
    colatitude_top = 0
lat_top = π/2 − colatitude_top
```

Положение края едино для всех уровней. Для выбранного уровня с точными размерами
`W × H`:

```text
lat_span   = 2π·H/W             # вертикальный охват, радианы
lat_bottom = lat_top − lat_span
```

Полный шар получается только при `H/W = 0.5` (тогда `lat_span = π`). Нижняя граница
зависит от точного отношения `H/W`, а не от числа целых тайлов: последняя (обрезанная)
строка тайлов не растягивается до южного полюса.

## Направление ↔ развёртка

Система координат: X — восток, Y — вверх, Z — север; нулевой азимут смотрит на север,
90° — на восток; наклон вверх положительный.

```text
# пиксель экрана → луч → координаты развёртки
phi = atan2(x, z)               # азимут от севера
theta = asin(y)                 # широта (вверх положительно)
u = fract((phi − radians(Origin[0])) / 2π)
v = (lat_top − theta) / lat_span

# развёртка → направление по (u, v)
az  = u·2π + radians(Origin[0])
lat = lat_top − v·lat_span
dir = (sin(az)·cos(lat), sin(lat), −cos(az)·cos(lat))
```

Если `v` вне `[0, 1]` — направление **не покрыто** снятой панорамой; рисуется тёмный
фон, а не растягивание до полюса. Горизонталь замыкается (шов 360°), вертикаль при
выборке крайних пикселей ограничивается границами изображения.

Внутри приложения та же пара (`lat_top`, `lat_span`) идёт и в фон-сферу
(`shaders/panorama.gdshader`), и в геометрию секторов (`shaders/pano_patch.gdshader`,
`pano_stream._dir_from_uv`), чтобы сектора ложились на фон без шва.

### Канонический охват

`lat_span` у разных LOD-уровней слегка разный (округление размеров в пикселях).
В приложении берём **один канонический** `lat_span` на панораму — по самому крупному
уровню (он точнее всего задаёт `H/W`), а `lat_top` — по самому мелкому. Это убирает
швы между тирами; погрешность для остальных уровней — доли градуса. Альтернатива —
считать `lat_span` строго по уровню (как в плеере), но тогда геометрию сектора
пришлось бы перестраивать при смене тира LOD.

## Почему «автомобильные» панорамы выглядят иначе

Формально формула одна для всех типов съёмки; «частичность» задаёт геометрия
конкретной панорамы. Но на выборке (Москва/Питер, 2026-11-12) корреляция чёткая:

| Слой | Полные 2:1 (`horizonTilt≈0`) | Частичные (`H/W≈0.31..0.38`, `tilt 22..33°`) |
|---|---|---|
| `stv` (уличные) | 88 | **34** |
| `sta` (воздушные) | **14** | 0 |

Пример частичной — «Малый Николопесковский переулок» (`y0maL6vrHpls`):
`17664×6172`, `H/W ≈ 0.349`, `Origin = [342.19, 27.106]` → охват зенит…−35.8°,
горизонт на **71.6 %** высоты (небо сжато в полоску). Пример полной — воздушная
`fplKsqYjdFHA`: `9216×4608`, `Origin = [235, 0]` → полный шар, горизонт по центру.

То есть **новые городские (автомобильные) панорамы** — это как раз частичные
развёртки, а **воздушные и парковые/пешеходные** — полные 2:1. Отсюда и ощущение
«для машин проекция другая»: у них снято не всё небо и надир.

### Проверка

- Метаданные: `curl -s "https://api-maps.yandex.ru/services/panoramas/1.x/?l=stv&lang=ru_RU&origin=userAction&provider=streetview&ll=37.5920,55.7510"`
  → `Zoom`/`Origin`.
- Офлайн-перепроецирование той же развёртки по формулам выше совпадает с живым
  плеером Яндекса; при подстановке «полного шара» (`v = acos(y)/π`) картинка уезжает
  (видны только стены, без дороги и неба).
- В приложении: `godot --path . --xr-mode off -- --shot --ll=37.5920,55.7510`
  (частичная) и `--shot --ll=37.6208,55.7539` (полная, регресс) — снимки в `user://dump/`.
